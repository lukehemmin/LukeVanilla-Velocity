## 소개

LukeVanilla-Velocity는 Minecraft 서버 네트워크에서 서버 간 메시징 및 서버 상태 모니터링을 제공하는 플러그인 시스템입니다. 이 가이드에서는 LukeVanilla-Velocity 시스템을 효과적으로 사용하는 방법을 배울 수 있습니다.

### 주요 기능

- **서버 간 메시징**: 서버 간 메시지를 전송하고 수신할 수 있습니다.
- **서버 상태 모니터링**: 서버의 온라인/오프라인 상태를 자동으로 모니터링합니다.
- **자동 플레이어 라우팅**: 서버 상태에 따라 플레이어를 적절한 서버로 라우팅합니다.

## 시스템 기능

### 서버 간 메시징

LukeVanilla-Velocity 시스템은 서버 간 메시지 전송을 위한 간단하고 안정적인 메커니즘을 제공합니다. 이 기능을 통해 다음과 같은 작업을 수행할 수 있습니다:

- 한 서버에서 다른 서버로 메시지 전송
- 프록시에서 모든 서버로 메시지 브로드캐스트
- 서버 간 명령어 실행 요청
- 플레이어 정보 공유

### 서버 상태 모니터링

서버 상태 모니터링 시스템은 다음과 같이 작동합니다:

1. 프록시는 주기적으로(30초마다) 각 서버에 핑 메시지를 전송합니다.
2. 서버는 핑을 수신하면 퐁 메시지로 응답합니다.
3. 프록시는 퐁 응답을 받으면 해당 서버를 온라인으로 표시합니다.
4. 지정된 시간(5초) 내에 응답이 없으면 서버를 오프라인으로 표시합니다.

### 자동 플레이어 라우팅

플레이어 라우팅 시스템은 다음과 같이 작동합니다:

1. 플레이어가 프록시에 접속하면, 시스템은 기본 서버(일반적으로 'survival')가 온라인 상태인지 확인합니다.
2. 기본 서버가 온라인이면 플레이어를 해당 서버로 연결합니다.
3. 기본 서버가 오프라인이면 플레이어를 대체 서버(일반적으로 'lobby')로 연결합니다.
4. 기본 서버가 다시 온라인 상태가 되면, 대체 서버에 있는 플레이어를 자동으로 기본 서버로 이동시킵니다.

## 명령어 가이드

### 서버 간 메시지 전송

- `/sendmessage <서버> <메시지>` (별칭: `/smsg`)
  - 특정 서버로 메시지를 전송합니다.
  - 권한: `lukevanilla.command.sendmessage`
  - 예시: `/sendmessage survival 안녕하세요`

### 플레이어 서버 이동

- `/sendplayer <플레이어> <서버>` (별칭: `/sendup`)
  - 특정 플레이어를 지정한 서버로 이동시킵니다.
  - 콘솔이나 게임 내에서 사용 가능합니다.
  - 권한: `lukevanilla.command.sendplayer`
  - 예시: `/sendplayer Steve lobby`

해당 명령어는 특정 플레이어를 강제로 다른 서버로 이동시킵니다. 주로 다음과 같은 경우에 유용합니다:

1. 관리자가 특정 플레이어를 이벤트 서버로 이동시키고 싶을 때
2. 플레이어의 서버 이동 문제를 해결할 때
3. 서버 점검 전 플레이어들을 다른 서버로 이동시킬 때

명령어를 실행하면 해당 플레이어는 자동으로 지정된 서버로 이동되며, 플레이어에게는 관리자에 의해 이동되었다는 메시지가 표시됩니다.

### Velocity 프록시 명령어

#### 서버 상태 확인 명령어

```
/serverstatus [서버명]
```

- **서버명**: (선택사항) 상태를 확인할 서버 이름

서버명을 지정하지 않으면 모든 서버의 상태를 표시합니다.

예시:
```
/serverstatus survival
```

출력 예시:
```
서버 상태:
- survival: 온라인
- lobby: 온라인
- creative: 오프라인
```

### Paper 서버 명령어

#### 프록시로 메시지 전송 명령어

```
/sendmsg <대상서버> <메시지>
```

- **대상서버**: 메시지를 보낼 대상 서버 이름
- **메시지**: 전송할 메시지 내용

예시:
```
/sendmsg lobby 모두 생존 서버로 와주세요!
```

#### 프록시에 서버 상태 보고 명령어

```
/reportstatus
```

이 명령어는 현재 서버의 상태를 프록시에 수동으로 보고합니다. 일반적으로 자동으로 수행되므로 문제 해결 목적으로만 사용해야 합니다.

## 서버 관리

### 새 서버 추가

LukeVanilla-Velocity 시스템에 새 서버를 추가하려면 다음 단계를 따르세요:

1. Velocity의 `velocity.toml` 파일에 새 서버를 추가합니다:

```toml
[servers]
  # 기존 서버 정의...
  
  # 새 서버 추가
  [servers.newserver]
    address = "127.0.0.1:25566"
    restricted = false
```

2. 새 서버에 LukeVanilla-Paper 플러그인을 설치합니다.
3. 필요한 경우 시스템 설정을 조정합니다.

### 서버 설정 조정

#### Velocity 설정

```toml
# velocity.toml
[servers]
  [servers.lobby]
    address = "127.0.0.1:25565"
    restricted = false
  
  [servers.survival]
    address = "127.0.0.1:25566"
    restricted = false

[plugins]
  [plugins.lukevanilla-velocity]
    # 기본 서버 설정 (플레이어가 처음 접속할 서버)
    default-server = "survival"
    # 대체 서버 설정 (기본 서버가 오프라인일 때 사용)
    fallback-server = "lobby"
    # 핑 간격 (단위: 초)
    ping-interval = 30
    # 핑 타임아웃 (단위: 초)
    ping-timeout = 5
```

#### Paper 서버 설정

Paper 서버에는 일반적으로 특별한 설정이 필요하지 않습니다. LukeVanilla-Paper 플러그인만 설치하면 됩니다.

## 메시징 시스템 활용

### 메시지 형식

다양한 메시지 형식을 사용하여 여러 기능을 구현할 수 있습니다:

#### 일반 메시지

```
/sendmsg <서버명> <메시지>
```

일반 텍스트 메시지를 다른 서버로 전송합니다.

#### 명령어 실행 요청

```
/sendmsg <서버명> cmd:<명령어>
```

다른 서버에서 명령어를 실행하도록 요청합니다.

예시:
```
/sendmsg survival cmd:say 서버 점검이 5분 후 시작됩니다.
```

#### 공지사항 메시지

```
/sendmsg <서버명> announce:<공지사항>
```

다른 서버에 공지사항을 전송합니다.

예시:
```
/sendmsg all announce:서버 점검이 5분 후 시작됩니다.
```

### 메시지 처리 예시

각 서버에서는 수신된 메시지를 목적에 맞게 처리할 수 있습니다. 예를 들어:

- `cmd:` 접두사가 있는 메시지는 서버에서 명령어 실행
- `announce:` 접두사가 있는 메시지는 모든 플레이어에게 공지사항으로 표시
- `teleport:` 접두사가 있는 메시지는 플레이어 텔레포트 요청으로 처리

## 서버 상태 모니터링

### 상태 확인 방법

서버 상태는 다음과 같은 방법으로 확인할 수 있습니다:

1. Velocity 프록시에서 `/serverstatus` 명령어 사용
2. API를 통해 프로그래밍 방식으로 상태 확인
3. 커스텀 GUI를 통한 시각적 표시

### 로그 확인

상태 모니터링 작업은 로그에 기록됩니다. 다음은 중요한 로그 메시지의 예입니다:

```
[LukeVanilla-Velocity] 서버 상태 확인 중...
[LukeVanilla-Velocity] survival 서버에 핑 전송
[LukeVanilla-Velocity] survival 서버에서 퐁 수신, 상태: 온라인
[LukeVanilla-Velocity] lobby 서버에 핑 전송
[LukeVanilla-Velocity] lobby 서버 응답 시간 초과, 상태: 오프라인
```

### 알림 설정

서버 상태 변경 시 관리자에게 알림을 보내는 기능을 구현할 수 있습니다:

1. `/alert` 명령어를 등록하여 알림 설정 관리
2. 특정 권한이 있는 플레이어에게 서버 상태 변경 알림 전송
3. Discord, Slack 등 외부 서비스와 연동하여 알림 전송

## 문제 해결

### 일반적인 문제 및 해결책

#### 서버가 항상 오프라인으로 표시됨

**원인**: 
- 서버와 프록시 간 통신 문제
- 방화벽 설정
- 플러그인 미설치 또는 설정 오류

**해결책**:
1. 해당 서버에 LukeVanilla-Paper 플러그인이 올바르게 설치되었는지 확인
2. 방화벽 설정 확인
3. 수동으로 `/reportstatus` 명령어 실행
4. 로그 파일 확인하여 오류 메시지 검토

#### 메시지 전송 실패

**원인**:
- 대상 서버가 오프라인
- 메시지 형식 오류
- 권한 부족

**해결책**:
1. 대상 서버가 온라인 상태인지 `/serverstatus` 명령어로 확인
2. 메시지 형식이 올바른지 확인
3. 충분한 권한이 있는지 확인
4. 로그 파일에서 오류 메시지 확인

#### 플레이어가 올바른 서버로 라우팅되지 않음

**원인**:
- 서버 상태 감지 문제
- 설정 오류
- 권한 문제

**해결책**:
1. 서버 상태가 올바르게 감지되고 있는지 확인
2. `velocity.toml` 설정에서 `default-server`와 `fallback-server` 값 확인
3. 플레이어 권한 설정 확인
4. 로그 파일에서 라우팅 관련 메시지 확인

### 로그 분석

#### 중요한 로그 패턴

문제를 진단할 때 다음과 같은 로그 패턴을 찾아보세요:

1. 서버 상태 변경 로그:
   ```
   [LukeVanilla-Velocity] 서버 [서버명] 상태 변경: [이전상태] -> [현재상태]
   ```

2. 메시지 전송 로그:
   ```
   [LukeVanilla-Velocity] [출발지서버]에서 [목적지서버]로 메시지 전송: [메시지내용]
   ```

3. 오류 로그:
   ```
   [LukeVanilla-Velocity] 오류: [오류메시지]
   ```

### 진단 명령어

#### 프록시 진단 명령어

```
/lukediag
```

이 명령어는 LukeVanilla-Velocity 시스템의 현재 상태에 대한 상세한 진단 정보를 표시합니다.

출력 예시:
```
LukeVanilla-Velocity 진단 보고서:
- 버전: 1.0.0
- 실행 시간: 3시간 45분
- 등록된 서버: 3 (온라인: 2, 오프라인: 1)
- 메시지 통계: 전송됨 (124), 수신됨 (98), 실패 (3)
- 최근 오류: 없음
```

#### 서버 진단 명령어

```
/lukepaper diag
```

이 명령어는 LukeVanilla-Paper 플러그인의 현재 상태에 대한 진단 정보를 표시합니다.

출력 예시:
```
LukeVanilla-Paper 진단 보고서:
- 버전: 1.0.0
- 실행 시간: 2시간 30분
- 프록시 연결: 활성
- 메시지 통계: 전송됨 (45), 수신됨 (67)
- 최근 핑/퐁: 30초 전
- 최근 오류: 없음
```

## 자주 묻는 질문

### 일반 질문

#### Q: LukeVanilla-Velocity는 어떤 Minecraft 버전을 지원하나요?
A: LukeVanilla-Velocity는 Velocity 3.0.0 이상을 지원하며, 이는 Minecraft 1.8부터 최신 버전까지 호환됩니다. Paper 플러그인은 Paper 1.16.5 이상을 권장합니다.

#### Q: 기존 서버 네트워크에 LukeVanilla-Velocity를 추가할 수 있나요?
A: 네, 기존 Velocity 기반 서버 네트워크에 쉽게 통합할 수 있습니다. 각 서버에 LukeVanilla-Paper 플러그인을 설치하고 Velocity 프록시에 LukeVanilla-Velocity 플러그인을 설치하기만 하면 됩니다.

#### Q: 다른 프록시 플러그인과 호환되나요?
A: LukeVanilla-Velocity는 대부분의 Velocity 플러그인과 호환됩니다. 그러나 플레이어 라우팅과 관련된 다른 플러그인이 있는 경우 충돌할 수 있으니 테스트해 보세요.

### 기능 관련 질문

#### Q: 플레이어를 특정 서버로 강제 이동시킬 수 있나요?
A: 네, `/connect <플레이어명> <서버명>` 명령어를 사용하여 플레이어를 특정 서버로 강제 이동시킬 수 있습니다.

#### Q: 서버 간 메시지에 플레이어 정보를 포함할 수 있나요?
A: 네, 메시지 내용에 플레이어 정보를 포함할 수 있습니다. 예를 들어 `playerinfo:PlayerName:level:25`와 같은 형식으로 전송하고, 수신 측에서 이를 파싱하여 처리할 수 있습니다.

#### Q: 메시지 전송에 필요한 최소 권한은 무엇인가요?
A: 기본적으로 `lukevanilla.command.sendmessage` 권한이 필요합니다. 관리자 명령어의 경우 `lukevanilla.admin` 권한이 필요할 수 있습니다.

### 성능 관련 질문

#### Q: 서버 상태 확인이 성능에 영향을 주나요?
A: 서버 상태 확인은 매우 가벼운 작업이며, 기본 30초 간격으로 수행되므로 성능에 미치는 영향은 미미합니다.

#### Q: 많은 수의 메시지 전송이 서버 성능에 영향을 줄 수 있나요?
A: 일반적인 사용량에서는 성능 문제가 발생하지 않습니다. 그러나 초당 수백 개 이상의 메시지를 전송하는 경우 성능에 영향을 줄 수 있습니다. 필요한 경우 메시지 배치 처리를 고려하세요.

#### Q: 대규모 서버 네트워크에서 LukeVanilla-Velocity를 사용할 수 있나요?
